# DHT11 连续读取失败与IRQ采集修订

日期：2026-11-09。板端数据由使用者采集；修订与离线验证在本机完成，未自动连接或测试开发板。

## 复测基线

用户提供10组温度/湿度读取：温度1次成功（32100），9次超时；湿度9次成功（36000或37000），1次超时。20次sysfs读取共10次成功、10次失败，仅第8组两项都成功。这不是20次独立测量：成功结果会缓存2秒，温度失败后紧跟的湿度读取又会触发一次新测量。

10条超时记录的边沿数为79、81、81、79、82、82、78、79、71、79；释放DATA到IRQ注册返回为38～57µs。该窗口与协议脉宽同量级，支持优先排查采集时序，但没有失败帧波形，不能据此确定所有丢沿均发生在开头。

## 修订内容：0.2.0-irq-first

1. 在发送起始拉低之前完成request_irq，避开释放后再注册的窗口。Rockchip配置IRQ触发时会切换GPIO方向，因此也不能在18ms拉低过程中注册。
2. 通过GPIOD_OUT_HIGH_OPEN_DRAIN取得DATA，随后释放为输入；仅驱动低或释放，保持外部3.3V上拉。gpiolib对开漏GPIO允许IRQ共用，普通推挽GPIO直接前移request_irq会遇到方向/占用约束。
3. 起始拉低期间不记录边沿；同步已执行的IRQ后开启采集，忽略主机释放时最初的高电平，从传感器响应下降沿开始。显式IRQF_NO_THREAD保持微秒采样在硬中断中进行。
4. 保持83沿完成唤醒；超时但已有82沿时尝试完整40位解码，与[Linux6.1参考驱动](https://github.com/torvalds/linux/blob/v6.1/drivers/iio/humidity/dht11.c)的容错边界一致。82并不自动等于有效，仍需电平、40位数据、校验和和数值范围全部通过。
5. 抽出共享纯帧解析器，补下降沿电平检查；只有整帧成功才更新温湿度及缓存。少于82沿不补造数据，仍报超时。
6. 增加MODULE_VERSION，可读取/sys/module/edge_dht11/version确认实际加载版本。新的日志字段为irq_setup_before_start和release_call，前者发生在起始信号前，不再是释放后漏采窗口。

GPIO开漏及输入释放语义见[Linux官方GPIO说明](https://docs.kernel.org/driver-api/gpio/driver.html#gpio-lines-with-open-drain-source-support)。当前SDK内核gpiolib允许开漏GPIO与IRQ共用；此修订仍需在目标板确认控制器行为和成功率，不将编译通过写成硬件修复完成。

## 当时的验证计划

手动加载新模块并核对版本后，关闭动态调试，仅连续读取温度10次，每次间隔3秒，明确记录每次返回码。每次新测量依然解析完整温湿度帧；这轮先不在温度失败后立即重试湿度，避免混淆独立测量成功率。再单独核对湿度节点和Agent真实传感器路径。
